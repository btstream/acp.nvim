*acp.nvim*  与 Agent 对话，界面参照 Zed 的 Agent Panel

==============================================================================
1. 简介                                                        *acp-intro*

acp.nvim 是一个 Neovim 原生的 Agent Client Protocol 客户端。
它不是把 Agent 的 TUI 嵌进终端窗口，而是用 buffer、split 和 extmark
自己渲染对话记录、工具调用和输入框。

默认连接 OpenCode：

    :!opencode auth login
    :Acp

默认布局为原生左右分屏；edgy.nvim 是可选依赖，使用时显式配置 external。
需要 Neovim 0.10+，推荐 0.12+。代码块语法高亮需对应语言的 Tree-sitter parser
与 highlights query；缺失时保留纯文本。界面文字为英文，默认使用 Nerd Font 图标。

==============================================================================
2. 命令                                                      *acp-commands*

:Acp [子命令]                                               *:Acp*
    toggle       打开或隐藏面板（默认）
    open         打开面板，必要时启动 Agent
    hide         隐藏面板，不中断会话
    new          新建会话
    stop         中止当前回合
    sessions     打开会话浏览器（<CR> 切换，<C-d> 删除，输入即过滤）
    delete       同 sessions，在浏览器内用 <C-d> 删除
    model        切换模型
    mode         切换模式
    reconnect    重连并恢复当前会话
    disconnect   停止 Agent 进程
    permission   重新打开待确认的权限请求
    file         把当前文件附加到输入区
    files        从项目索引选择文件，插入 @引用，不打开文件或发送消息
    image        读取剪贴板图像并附加；带路径时附加该文件
    diagnostics  把当前 buffer 的诊断附加到输入区

:AcpLog                                                      *:AcpLog*
    打开日志文件。

:AcpCompletionRefresh                                *:AcpCompletionRefresh*
    清理项目文件索引缓存，下次补全或选择文件时重新扫描。

:AcpDebug                                                  *:AcpDebug*
    在命令行打印控制器状态。

工作指示器                                                  *acp-spinner*

输入区 spinner 使用 libuv timer，默认 ui.toolbar.animation_interval=120ms；UI 回调合并，
明确刷新 ACP 窗口 winbar，必要时回退 redrawstatus!。不切换窗口焦点。隐藏面板/切换到
其他标签页时停止，返回后恢复；已停止/关闭的 handle 在下一次状态、窗口、焦点同步时重建。

:AcpDebug 的 spinner 包含：
  state / timer_active            动画状态及 handle 是否存活
  ticks / frame_changes           主线程 tick 和帧变化计数
  last_tick_age_ms                距最近一次 tick 的时间
  max_tick_gap_ms                 历史最大 tick 间隔，不只包含解析耗时
  max_schedule_delay_ms           UV 回调到 scheduled UI 上下文的最大等待
  max_refresh_delay_ms            合并刷新任务在队列中的最大等待
  bar_evaluations                 winbar 表达式求值次数，不是物理屏幕绘制次数
  last_evaluated_frame            最近求值的运行中 spinner 帧
  redraw_backend                 targeted_winbar 或 redrawstatus!
  active_errors / last_error      当前错误阶段 / 最近历史错误

apply、redraw、tick、start 错误分别计数，每个连续错误阶段仅首次记日志，成功后允许再次报告。
API 版本不支持定向重绘时会记录 targeted_fallbacks / last_targeted_error 并使用兼容路径。
state=static 表示 ui.toolbar.animate=false，last_bar_status=waiting 表示等待权限，不是卡死。
动画按单调时间选择帧，不补放积压。主循环忙时仍会暂停；libuv 不提供后台线程上的 UI 绘制。
可结合 render.timings（ui.render.profile=true）和 transport 统计定位重型同步工作。

python3 tests/integration_spinner.py 是带 UI 的回归，需要额外测试依赖 pynvim。

3. 输入区                                                    *acp-composer*

进入 acp_input 窗口或缓冲区时自动切换到插入模式，离开时退出插入模式，避免把输入状态
带到转录区或编辑窗口。按 <Esc> 可暂时使用普通模式；离开后再次进入时恢复插入模式。

以下均为默认值，可用 keymaps.input 修改（见 |acp-keymaps|）。

<C-s>          发送；回合进行中且输入为空时改为中止
               keymaps.input.send
<C-c>          中止当前回合（普通模式）
               keymaps.input.cancel
q              隐藏面板（普通模式）
               keymaps.input.close_panel
<C-]>          附加当前选区（普通模式）
               keymaps.input.add_selection
<M-m> / M      切换模型（输入 / 普通模式）
               keymaps.input.pick_model
<M-b> / m      切换模式（输入 / 普通模式）
               keymaps.input.pick_mode
L              历史会话（普通模式）
               keymaps.input.pick_session
<C-x><C-u>     补全 /命令 与 @文件（Vim 内置触发，不可配）
@path/to/file  发送时自动展开为附件

winbar 左侧显示模式徽标、模型名与可选用量；右侧显示状态图标/动画与队列数量。
模型名不显示 provider 前缀，选择器仍保留完整名称。模式徽标和模型名可以点击。
普通选择器默认调用 vim.ui.select；过滤能力取决于用户接管它的 UI。

每个会话有独立的草稿和附件。面板隐藏后草稿仍保留。

4. 转录区                                                  *acp-transcript*

以下均为默认值，可用 keymaps.chat 修改（见 |acp-keymaps|）。

i / <C-s>      聚焦输入区
               keymaps.chat.focus_input
<CR>           打开光标所在位置的文件
               keymaps.chat.open_location
<Tab>          展开或折叠工具/思考块；不可折叠时聚焦输入区
               keymaps.chat.toggle_block
[b / ]b        上一个 / 下一个消息块
               keymaps.chat.prev_block / keymaps.chat.next_block
G / gg         最新 / 最早
               keymaps.chat.scroll_bottom / keymaps.chat.scroll_top
S              附加当前选区
               keymaps.chat.add_selection
F              附加当前文件
               keymaps.chat.add_file
R              附加诊断
               keymaps.chat.add_diagnostics
M / m          选择模型 / 模式
               keymaps.chat.pick_model / keymaps.chat.pick_mode
<C-n>          新建会话
               keymaps.chat.new_session
L              历史会话
               keymaps.chat.pick_session
g?             帮助（内容按当前配置生成）
               keymaps.chat.help
q              隐藏面板
               keymaps.chat.close_panel

所有按键都是 buffer-local，不会污染全局映射。转录区只读，从输入区或其他窗口直接
切入时也会退出插入模式。默认 i / <C-s> 切到输入区，S / R 保留附加选区 / 诊断动作；
未绑定业务动作的插入入口（如 a、o、A、gi）静默忽略。关闭 focus_input 后 i 也静默
忽略。keymaps.chat 配置的业务映射优先于这些兜底映射。

工具调用卡片折叠时只显示标题和一行预览。展开后，execute（shell）调用会在输出
之前以 "$ 命令" 的形式显示完整命令行：优先取 agent 的 rawInput.command，没有
结构化输入时退回标题。标题栏仍会为适配面板宽度截断长命令，卡片内是完整文本。
多行命令逐行显示，命令与输出之间留一个空行。

文件修改的卡片标题区分 Edit 与 Write。ACP 没有 write kind，创建/覆盖文件也报成
edit，因此插件按工具输入判断：带旧内容（oldString / oldText / patchText）的是
Edit，只有新内容（content 等）的是 Write；输入未到达时退回标题里的 write/create。

edit / write / patch 的卡片展开后直接画出 diff：删除行用 DiffDelete 背景，新增
行用 DiffAdd，+/- 号单独配色，上下文行沿用卡片底色。只有一个 hunk 时不显示 @@
头，多个 hunk 才用它分隔。一次涉及多个文件时，文件之间画一条分隔线。超过
ui.diff.max_lines 或 ui.diff.max_bytes 时以一行
提示收尾，不会把整个文件倒进 buffer。

diff 行按被编辑文件自身的文件类型着色（.lua 用 Lua、.py 用 Python），颜色来自
treesitter 的 @capture 组，与普通 buffer 一致；红绿背景与语法前景同时生效。只解析
"要显示的几行"，成本与文件大小无关（30 行约 0.6ms，800 行约 13ms），并按内容缓存，
流式刷新几乎零成本。缺 parser、扩展名未知或超过 ui.diff.max_syntax_rows 时静默
退化为纯文本，diff 本身不受影响。ui.diff.syntax = false 可整体关闭。

这些卡片默认展开。agent 仍在执行时就会用 rawInput 里的变更出图，完成后替换为
权威的 diff。按 <Tab> 手动折叠后，后续更新不会再弹出；从历史加载或重连恢复的
卡片默认折叠，避免一次展开几十个 diff；回放提交后再产生的新 diff 恢复默认展开，
历史卡片保持折叠；同进程内切回缓存会话时保留原状态。
write 拿不到旧内容，按"全新增"展示并标注 (new content)。

5. 键位配置                                                *acp-keymaps*

    require("acp").setup({
      keymaps = {
        input = { send = "<C-CR>" },                        -- 单个键
        chat = {
          focus_input = { "i", "<C-s>" },                   -- 多个键
          toggle_block = "<C-t>",
          scroll_top = false,                               -- 关闭该绑定
        },
      },
    })

每个字段接受：单个键、键的列表、{ n = "...", i = "..." } 模式表，或 false。
只会绑定该动作实际声明的模式；转录区没有输入模式，因此那里写成
pick_model = { n = "T", i = "<M-t>" } 时 i 会被忽略。
两个动作在同一模式抢同一个键会在 setup() 时报错；<Tab> 与 <C-i>、<CR> 与 <C-m>
视为同一个键。按键必须写在所属视图下：直接写 keymaps.send 会报错，并提示
应写成 keymaps.input.send。

可配置的字段与默认值见 |acp-composer| 与 |acp-transcript| 两张表。
picker、会话浏览器等自绘浮窗内部的按键不在 keymaps 管辖范围内。

7. 与 edgy.nvim 集成                                          *acp-edgy*

    require("acp").setup({ layout = { backend = "external" } })

    -- edgy 配置
    opts = function(_, opts)
      require("acp.integrations.edgy").extend(opts)
    end

两个视图必须作为数组元素写进列表，不能写成具名字段。edgy 只遍历
ipairs(views)，具名字段会被完全忽略，导致输入框脱离 edgebar、布局错位：

    -- 正确
    right = {
      { ft = "acp_chat", title = "Agent", wo = { winbar = false } },
      { ft = "acp_input", title = "Message", size = { height = 8 },
        wo = { winbar = false } },
    }

    -- 错误
    right = {
      { ft = "acp_chat", title = "Agent" },
      input = { ft = "acp_input", title = "Message" },
    }

无法接管时 acp.nvim 会给出警告。

acp 创建两个普通视图：

    acp_chat    对话记录（只读）
    acp_input   输入区（可编辑）

由 edgy 决定它们的位置和尺寸。acp 不会持续调整窗口大小，也不会在窗口
被关闭后强行重开。

默认 acp 拥有两个 winbar。若想让 edgy 显示标题栏：

    require("acp.integrations.edgy").extend(opts, {
      title_winbar = true,
      toolbar_winbar = false,
    })

并将 ACP 的 ui.title.placement 与 ui.toolbar.placement 设为 "off"。
views() 返回 { chat = ..., input = ... }，不能直接赋给 opts.right；使用 extend()
或手动将两项作为数组元素插入。左侧布局显式传 position = "left"，并同步 ACP
的 layout.position。

8. 状态栏                                                  *acp-statusline*

acp.nvim 不修改 'statusline' 和 'laststatus'。交互信息全部放在输入窗口的
winbar 中，因此 laststatus=3（全局状态栏）下也能正常显示。

需要集成到自己的状态栏时：

    require("acp").statusline()   -- "◆" / "◆ ◌" / "◆ !"
    require("acp").status()       -- 结构化表

9. 窗口保护与选择器                                        *acp-protection*

ACP 的两个窗口默认锁定到自己的 buffer（'winfixbuf'），:edit、:bnext 等操作
无法把对话记录或输入框替换成其它文件。关闭窗口与隐藏面板不受影响。

从面板 :split 会得到一个可用的普通窗口，而不是被锁死的副本。

需要关闭该行为：

    require("acp").setup({ layout = { lock_buffer = false } })

普通选择器（模型、模式、权限确认）默认通过 vim.ui.select 实现，
因此 telescope、fzf-lua、snacks.nvim 等插件会自动接管。需要改用内置浮动
选择器时：

    require("acp").setup({ ui = { picker = "internal" } })

会话浏览器独立使用 ui.session_picker，默认 snacks，不可用时回退到内置窗口。

==============================================================================
10. 工作目录                                                  *acp-cwd*

会话的工作目录默认与 Neovim 的 cwd 一致（vim.fn.getcwd()），可用 cwd 配置项
显式固定。:Acp sessions 的列表按该目录过滤；若为空，会自动退回展示 Agent 知道
的所有会话。

切换历史会话时使用该会话自己的目录发起 session/load，因为 ACP 规范要求 cwd 与
会话一致，不匹配时 Agent 会拒绝。

11. 面板尺寸                                                    *acp-sizing*

原生布局中 layout.width 为 0.05~1 时按编辑器宽度取比例，>1 时为绝对列数。
先应用 min_width / max_width，再限制为编辑器宽度的 60%；空间不足时可能小于
min_width。输入高度受 min_input_height / max_input_height 约束。external 模式
由布局管理器设置尺寸。两个窗口的局部 statuscolumn 均设为一个空格 " "。

构建面板时临时关闭 'equalalways'，两个窗口创建完并设置好尺寸后再恢复；否则
第二次 split 会立即重排，覆盖配置的宽度。

acp_chat 宽度变化时会自动重新排列表格、卡片和分隔线；拖动分屏、调整编辑器尺寸及
edgy 调整宽度均适用。连续调整采用 100ms 防抖，期间流式内容继续按上一次稳定宽度更新。
仅高度变化或其它窗口调整不会触发完整排版。阅读历史时尽量保留所在 block 的行偏移及
视口，不将重排标记为新消息；跟随输出时保持底部。隐藏后重开按实际窗口宽度重排。

鼠标需在当前模式启用：默认 'mouse' 为 "nvi"，已支持普通、可视和插入模式，
并不要求包含 a。设为空字符串会关闭鼠标支持。无法点击时也可用 <M-m>/<M-b>。

12. 会话标题与删除                                      *acp-session-titles*

标题显示在对话记录窗口的 winbar 中。为兼容未推送 session_info_update 的 Agent，
acp.nvim 在会话创建后、切换会话后及每回合结束后查询 session/list 来同步标题，
并按 session id 缓存；同时支持 Agent 推送的标题更新。
历史先重放到暂存对象，成功后提交；失败不覆盖旧历史与队列。同一时间只执行一次重放。
选择运行中的缓存会话时直接查看，不重新加载；旧加载结果不会覆盖较新的选择意图。

:Acp sessions 默认使用 snacks.nvim 的 picker：自带 fuzzy 搜索、实时预览，并沿用
用户已有的 snacks 主题。未安装 snacks 时自动回退到内置窗口。

    <CR>        切换会话
    <C-d>       删除会话（二次确认）
    输入        fuzzy 过滤
    <Esc>/q     关闭

列表右侧显示更新时间，当前会话行首有箭头标记，右侧预览显示完整会话 ID、目录与
时间。删除后列表原地刷新，可连续删除。

强制使用内置窗口：

    require("acp").setup({ ui = { session_picker = "internal" } })

内置窗口（回退时）支持 j/k 移动与 <BS>/<C-u> 编辑过滤。
q 关闭，gg/G 跳到首项/末项；需要搜索保留字母 j/k/q 时用大写 J/K/Q。

删除非当前会话不影响当前对话；删除当前会话会自动新建一个。Agent 未声明
sessionCapabilities.delete 时给出提示，不弹出无法兑现的确认框。

13. 行为细节                                                *acp-behavior*

同一会话同时只运行一个 prompt；生成中提交的消息本地排队。
默认最多排队 16 条、估算载荷 4 MiB，超过时拒绝入队并保留输入。
队列属于会话运行时，切换窗口不暂停后台队列；历史替换共享 outbox，不丢失待发送消息。
队列仅保存在当前 Neovim 进程，退出或崩溃后不恢复。

重新 setup() 会取消旧环境任务；待发送队列非空时默认拒绝重新配置。确实需要丢弃时：

    require("acp").setup({}, { discard_queued = true })

Agent 崩溃后使用 :Acp reconnect。重连会通过 session/load 重放 Agent 侧
历史，但不会自动重发上一条 prompt。
断连暂停队列；恢复当前会话后继续尚未开始的消息，其他会话在选中并恢复后继续。
已发请求不自动重试，避免重复工具操作；这不是远端执行 exactly-once 保证。

未发送的草稿保存在 stdpath("state")/acp/drafts.json，重启后自动恢复。
磁盘草稿最多 50 条，内存历史草稿默认最多 20 条。磁盘保存合并 150ms 后异步写入，
退出时 flush；崩溃可能丢失尚未持久化的最近修改。
草稿保存显式绑定项目与会话，切换或重入不会误写另一个会话；仅附件的草稿也会保留。

控制器使用 block 版本和变更日志，仅重建变化块及受影响的后缀。窗口宽度变化、主题
切换或变更日志落后时使用完整渲染。代码语法缓存跨宽度复用，最多 64 项/约 2 MiB；
超过 256 KiB 的单个代码块显示纯文本，单块最多保留 20,000 个语法捕获。

memory.* 限制本地保留载荷，不是 Lua/Neovim RSS 硬上限。超大 block 显示截断标记，
会话超预算会移除最旧记录，不修改 Agent 侧历史；重新加载仍应用同样预算。
闲置会话按 LRU 淘汰，当前、运行中、有队列或权限请求的会话受保护，可暂时超过
缓存数量/总载荷预算。渲染缓存和 Neovim 对象仍有额外开销。

可选懒渲染                                                   *acp-lazy-render*

默认 ui.render.lazy_syntax=false，ui.render.pagination.enabled=false，保留原有全文路径。
建议先开启 lazy_syntax（A），再按需开启 pagination.enabled（B）：
>
    ui = { render = {
      lazy_syntax = true,
      profile = false,
      budget_ms = 4,
      overscan = 1,
      commit_rows = 2000,
      pagination = {
        enabled = false,
        page_blocks = 64,
        max_blocks = 192,
        page_bytes = 256 * 1024,
      },
    } }
<
A 保留全文文本、conceal、基础高亮和背景，只按视口延迟代码及 diff 的语法装饰；
原生搜索、复制、位置跳转不变。语法缓存有独立预算，远处的语法 extmark 会清理。
B 按连续 block 范围物化历史，分页排版逐 block 让出主循环。最新消息始终自动追加；只有更早
的历史按需加载，接近顶部时预取相邻页，顶部保留“更早消息”提示，可按键加载。
gg 加载最早保留内容，G 回到最新并跟随，[b/]b 可跨页。

接收尾部、分页排版、语法装饰与大型提交使用共享调度器；接收首次回调与消息派发仍有独立预算。
stdout 未处理尾部保序排队并计入积压限制，溢出时明确断连；分页中的表格、Markdown 在结构行边界让出；
超过 commit_rows 的首次布局或翻页提交按行分片，期间可继续响应输入与刷新 spinner。
分片依赖协作式让出，单个 JSON 解码、一次 Treesitter 解析、diff 计算、非分页排版和单条消息分帧仍不可抢占。

分页开启后，原生 /、Visual 复制只覆盖已加载文本；不提供全历史原生搜索。Session 与
Agent 历史不变，Chat:transcript() 显式全文导出仍完整，但会临时执行全量文本排版。
最新消息不受分页限制，始终物化并自动追加；往回加载只会扩展旧侧窗口，不会隐藏新内容。
返回底部时旧侧窗口收回预算，可见内容与操作中的卡片受保护，因此预算不是硬上限。
Visual/Select 选区活动时暂停分页物化修改，退出后自动补齐最新内容。
单个 block 不做块内分页，继续受原有 memory.* 限制。
page_bytes 是旧侧每页的源载荷目标；回收同时参考 max_blocks 和页面数量推导的字节预算，
不是 RSS 上限。完整 JSON 解码、单块排版及单次 Treesitter 解析仍不可抢占。

profile=true 时 :AcpDebug 的 render 展示分层 timings、物化行数、缓存块数、语法 extmark
数量及分页范围。每个阶段除 count/total/max 外还有按 1/2/4/…/1024ms 的延迟桶与溢出计数；
slow_tasks 保留最近 20 条超过 8ms 的任务（名称、耗时、block id/kind/工具类型/载荷规模，
不含正文）。first_paint 是首个布局提交耗时，不是物理屏幕绘制耗时；layout_slice 是分页
排版时间片，block_layout 是单块排版，syntax 是实际装饰解析调用耗时，write 含分片提交。
transport 统计另有输入重入计数，可与 spinner 的 max_tick_gap_ms 交叉定位。

transport.max_pending_bytes 默认 64 MiB，限制尚未消费接收数据（不完整消息、待分发
消息、尚未完成的文本分片、在途写入与已读缓冲）的估算开销；设为 0 关闭积压上限。
spill_bytes 默认 64 MiB，是完整 JSON 行异步落盘的工作集目标；设为 0 则只占内存。
两者为正时，落盘阈值最多为上限的 75%。磁盘旧消息优先于内存新消息，当前文本分片
又优先于所有后续消息。回调时间预算到期后，未处理的输入尾部进入共享调度队列，
下一片继续解析，保持顺序且不丢弃；输出批次超出预算时同样让出。
阈值不是 RSS 硬上限：输入回调、JSON 对象和临时复制仍有额外开销；磁盘慢于输入时，
有限预算仍可能触发断连。单条 JSON 解码、工具替换更新或单块排版仍不可抢占。

超过 transport.text_chunk_bytes 的文本型 session/update 会在完整解码后按 UTF-8 边界
切片，通过惰性派发器直接归约已解码片段，不重新编码或进入分片检测；片间可让出主循环。
仅处理 agent/user/thought 追加文本。工具内容、diff 和 rawOutput 保持原子替换，避免
累计前缀的二次方复制；其它消息仍整条处理。完整 JSON 解码的峰值内存仍然存在。

落盘文件位于 `stdpath("run")/acp.nvim/acp-spill-*`，权限 0600，排空、停止或退出时删除；
停止时若尚有 I/O，等待其回调后释放文件描述符。创建/写入失败回退内存；读取失败明确
报错并断连，不在缺失消息后继续运行。超过 24 小时的崩溃残留会在下次启用落盘时清理。
文件是原始协议正文，未加密。

`max_pending_bytes = 0` 且 `spill_bytes = 0` 时永不因总积压断开，代价是可能耗尽内存，
只适合确定历史规模的环境。回放期间超限日志会带 `phase=replay`；摘要包含积压、上限、
触发行大小、本次回调消息数、累计消息/字节、最大输入、落盘记录与批次耗时，不含正文。
16/64/256/1024 MiB 会各告警一次。开启 `log.protocol` 还会逐回调记录明细。
通知归约在该预算内执行；权限 UI 单独调度，旧连接的模型/权限选择器不会影响新状态。

思考块在流式期间实时展开并显示 Thinking，结束后自动折叠并显示 Thought；历史与重连
重放保持折叠。跟随时超过一屏的内容保持尾部锚定，保留原有尾部空行，后续内容继续追加。
不足一屏时从顶部显示，不添加顶部留白；鼠标不能继续下滚来扩大自然剩余空白。聊天窗口启用
局部 smoothscroll，处理高于一屏的换行文本；不改变其它窗口的滚动设置。
鼠标上滚离开末尾暂停自动跟随，下滚回到实际末尾恢复跟随并清除新消息提示，不依赖光标位置。
暂停跟随不暂停消息接收或 buffer 追加；自动折叠、重排和其它窗口的滚动不会触发恢复跟随。
手动 <Tab> 优先。ui.thoughts.expand_while_streaming / collapse_on_finish
可关闭对应行为。

权限选择器按 Esc 或 q 关闭视为拒绝；若 Agent 没有提供 reject 选项，则返回
cancelled。

14. 轮次分隔符                                          *acp-separator*

每两轮对话之间画一条细分隔线。默认中间一个圆点：

    ────────────────────────── ● ──────────────────────────

ui.separator.form 控制样式：

    "dot"    细分隔线 + 居中圆点（默认）
    "turn"   细分隔线 + 轮次，形如 `Turn 2`
    "off"    不画分隔符

    require("acp").setup({

    })

上面时 <Tab> 不会误展开相邻的卡片。

15. 高亮                                                    *acp-highlights*

样式为静态定义，多数组链接到 Neovim / Tree-sitter 组；模式徽标默认使用固定颜色，
可通过 ui.highlights 覆盖。插件不会在运行时混合主题颜色。
正文里的 Markdown（粗体、斜体、删除线、标题、引用、链接）链接
到 treesitter 的 @markup.* 捕获组，所以在对话记录里的呈现和普通 Markdown buffer
遵循相应主题样式，但并非完整的 Markdown 实现。

两处例外，都是为了让表格读起来安静一些：

- 行内代码链接到 String。@markup.raw 在多数主题里是暖色强调色，放在正文中
  会抢注意力。
- 表格边框链接到 NonText。@punctuation.special 会被主题染成橙色、品红之类
  的高亮色，整个表格会变成霓虹网格。

常用的组：

    AcpUser  AcpAssistant  AcpToolTitle  AcpToolRunning
    AcpToolSuccess  AcpToolError  AcpPlan  AcpSeparator
    AcpTitle  AcpToolbar  AcpPermission  AcpStreaming
    AcpUserIcon  AcpUserTitle  AcpAssistantIcon  AcpAssistantTitle

工具卡片里的 diff 使用主题自带的 diff 组，红绿配色与 review 窗口一致；行内文字
另按所在文件的 treesitter @capture 着色，两层叠加而不是互相覆盖：

    AcpDiffAdd  AcpDiffDelete  AcpDiffAddSign  AcpDiffRemoveSign
    AcpDiffHunk  AcpDiffMeta  AcpDiffFile

AcpDiffAdd / AcpDiffDelete 是整行背景（链接 DiffAdd / DiffDelete），+/- 号单独
成组，便于主题只给背景色时单独调整；AcpDiffMeta 同时用于卡片内的分隔线与
"已省略 N 行"提示。

插件自绘的 picker（ui.picker = "internal" 的选择框、:Acp sessions 的内置窗口）
使用另一套 AcpPicker* 组，默认链接到主题组：

    AcpPickerNormal  AcpPickerBorder  AcpPickerTitle
    AcpPickerSelection  AcpPickerItem  AcpPickerMatch
    AcpPickerCurrent  AcpPickerCurrentItem  AcpPickerDescription
    AcpPickerMeta  AcpPickerEmpty  AcpPickerSeparator
    AcpPickerPrompt  AcpPickerFooter

AcpPickerNormal / AcpPickerBorder / AcpPickerTitle 通过 winhighlight 映射到浮窗
的背景、边框和标题，所以能在 style = "minimal" 的浮窗里单独改色，不必修改全局的
NormalFloat。AcpPickerItem 链接到 Normal：浮窗里 Normal 已被 winhighlight 映射到
AcpPickerNormal，snacks 列表里它则保持列表自身的背景色。snacks 后端的会话浏览器只用行内的组
（AcpPickerItem / AcpPickerCurrent / AcpPickerCurrentItem /
AcpPickerDescription / AcpPickerMeta），窗口外观沿用用户自己的 snacks 主题。

acp_chat 的标题栏（winbar）与正文共用同一个背景（AcpNormal），读起来是对话记录
的页眉，而不是一条独立的色带。acp_input 的工具栏仍然用 StatusLine 的颜色，因为
它是工具栏而非页眉。

对话记录的标题行拆成图标和文字两组。默认 AcpUserTitle 链接到
AcpUserIcon；助手的两组均链接到 Keyword。想区分时
单独覆盖即可。助手回合开头的 Markdown 标题会用 AcpAssistantTitle，正文中间
的标题仍保留各自的 AcpH1-AcpH4 级别。

两种覆盖方式，都会优先于内置定义。通过 setup 传入：

    require("acp").setup({
      ui = {
        highlights = {
          AcpUser = { link = "Function" },
          AcpToolTitle = { fg = "#7aa2f7" },
        },
      },
    })

或者随时直接设置：

    vim.api.nvim_set_hl(0, "AcpUser", { link = "Function" })

切换 colorscheme 后会重新应用内置定义和 ui.highlights 配置；直接 nvim_set_hl 的
临时覆盖不保证保留，需要持久化时使用配置或自己的 ColorScheme 回调。
工具栏在 Neovim 0.12+ 使用继承背景的高亮语法；0.10/0.11 使用兼容语法，外部布局
插件重映射 WinBar 时颜色可能有所不同。

ui.icons = false 会改用 ASCII 图标。

17. 输入区补全                                               *acp-completion*

默认用 <C-x><C-u> 补全 /命令 和 @文件；索引异步建立，完成后显示原生菜单。
可选 blink.cmp / nvim-cmp 原生 source（选择一个），只在 acp_input 中生效。
两者共用解析器、文件索引与替换范围，保留当前会话命令说明，不执行命令或自动发送。

blink.cmp：将 sources 合并进已有 setup/opts： >lua
    sources = {
      per_filetype = { acp_input = { "acp" } },
      providers = { acp = { name = "ACP", module = "acp.completion.blink" } },
    }
<
nvim-cmp：在两个插件可 require 后注册并设置 filetype 配置： >lua
    local cmp = require("cmp")
    require("acp.completion.cmp").setup()
    cmp.setup.filetype("acp_input", {
      enabled = true,
      sources = { { name = "acp", keyword_length = 0 } },
      matching = { disallow_symbol_nonprefix_matching = false },
    })
<
不修改全局 sources 和映射；若自己的 enabled 排除了 nofile buffer，需要放行 acp_input。
建议 <C-s> 发送，框架按键确认补全；如用 <CR> 发送，必须自行处理菜单选中项优先确认。
完整 lazy.nvim 示例见 examples/completion_blink.lua 与 examples/completion_cmp.lua。

@ 引用支持无扩展名、中文、空格和引号。带特殊字符时使用 JSON 字符串语法：
    @Makefile  @lua/acp/init.lua  @"docs/中文 file.txt"
邮箱中的 @ 不匹配。补全与发送使用相同语法；发送时才附加可读文件，不预读所有文件正文。

completion 默认值： >lua
    completion = {
      native = true, max_items = 200, picker = "vim",
      files = {
        backend = "auto", command = false, root = false,
        hidden = true, ignored = false, cache_ms = 10000,
        max_bytes = 16 * 1024 * 1024, max_projects = 4,
      },
    }
<
auto 依次选 rg --files、fd/fdfind、git ls-files，最终回退异步目录遍历。内置遍历不解析
ignore 文件，建议安装 rg/fd。root=false 从会话 cwd 找 Git 根目录，否则用会话 cwd；
也可设绝对路径或 function(cwd) return root end。插入路径始终相对会话目录。
hidden/ignored 遵循所选工具规则，.git 固定排除。ignored=true 可能显示敏感的被忽略文件。
command 可设 argv，cwd=root，要求输出 NUL 分隔路径；不会拼 shell 字符串或把查询当命令。
max_bytes 估算索引路径和条目开销，不是总 RSS 限制；超限明确报错，不悄悄截断。
max_items 只限制原生菜单，先匹配完整索引再截取；框架与文件选择器获得完整索引。

:Acp files / require("acp").pick_file() 使用 completion.picker 选择完整项目索引中的文件，需先打开输入区。
picker 可选 vim（vim.ui.select）、fzf-lua、snacks、telescope，不设强依赖；缺少所选工具时报错。
也可 require("acp").pick_file({ backend = "fzf-lua" }) 单次选择。可选映射：
    keymaps = { input = { pick_file = "<M-f>" } }
默认不占用按键；选择后插入引用并回到输入区，与 :Acp file 附加当前文件不同。
取消、会话切换、buffer 销毁或查询过期后，旧结果不会修改输入。

18. 图像附件                                             *acp-images*

输入区可附加图像，以 ACP image 内容块发送。要求 Agent 声明
promptCapabilities.image（OpenCode 支持）；未声明时内嵌图像会被明确拒绝，
不会等到发送后才由 Agent 报错。resource_link 形式不受此限制。

用法：
    :Acp image              读取系统剪贴板中的截图并附加
    :Acp image path/to.png  附加指定文件
    直接粘贴 / 拖拽图像文件路径（只对输入区生效）

Lua API：require("acp").paste_image()、require("acp").add_image(path)。

配置： >lua
    context = {
      images = {
        enabled = true,
        max_bytes = 3 * 1024 * 1024,
        max_per_message = 4,
        clipboard = "auto",  -- 或 false，或自定义 argv
        path_mode = "link",  -- "link" | "inline"
        ttl_hours = 24,
        max_cache_bytes = 64 * 1024 * 1024,
      },
    }
<
clipboard = "auto" 依次尝试 wl-paste、xclip、pngpaste、powershell.exe。
也可给 argv（stdout 即图像字节），以复用已有截图工具。

paste_image 默认绑定 <C-v>（普通与插入模式），与 OpenCode TUI、pi 的习惯一致。
这会覆盖输入区的 i_CTRL-V（字面量插入）和普通模式 CTRL-V（块选择），
仅在 acp_input 内生效。需要换键时：
    keymaps = { input = { paste_image = "<M-v>" } }

图像在 acp_input 粘贴光标处插入 [Image 1] 可编辑占位符，多张图片独立编号，不放在 winbar。
默认浅黄色底、深色粗体，可通过 ui.highlights.AcpInputImage 覆盖。
这不是像素预览；光标放在占位符之后，可正常移动到两侧。在后方按退格或前方按 Delete
整块删除附件，支持撤销/重做。发送时移除受跟踪的占位符，不影响用户手写的同名文字。
ACP 内容块按输入区的文字/图片顺序交错发送；聊天记录也在原位置显示图片编号，
不把图片挪到标题或末尾。排队消息保存独立的位置快照，不受后续输入编辑影响。
异步读取的位置跟随文本编辑；清空或切换草稿后丢弃旧结果，不抢焦点、不强制恢复插入模式。

为什么不使用终端的粘贴快捷键：终端只在 bracketed paste 中传文本，截图不会
到达 Neovim；OSC 5522 需要终端专用协商并改变普通粘贴处理，本插件暂不接入。
目前由插件主动读取剪贴板，与 OpenCode TUI、pi 等终端客户端一致。

图像只在发送时编码。草稿、本地队列和会话块只保存路径、大小与 sha256，避免
base64 在三处各放大 33%。字节存放在 stdpath("state")/acp/images（目录 0700、
文件 0600），按 ttl_hours 与 max_cache_bytes 回收。max_bytes 会与
